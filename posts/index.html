2026年8月25日 一直被错误设计的 HTTP API 参数校验模式

传统 Web Framework 对接口参数校验的模式通常如下：

  1. 为每个参数绑定一个 Validator 定义
  2. 调用 Validation 对所有参数进行校验
  3. 如果验证失败则返回客户端一个错误列表，包含每一个验证失败的参数以及失败原因

但上述模式是一种错误的设计。接口调用隐含了契约，应该由调用者来保证参数满足契约，而不该由被调用接口来校验参数甚至返回错误列表，这是一种职责错位。接口只负责业务相关的参数检查；对于违背契约的请求，直接拒绝并返回一个 ContractViolation 错误即可。在网页应用的场景里，参数校验应该前置到前端代码中。当然，这一切的前提是有明确、规范的文档定义。
